# 报告设计规范（HTML / Excel / Markdown）

这份文档记录经过九轮真实反馈定稿的视觉与文案规则。**改样式前先读，改完必须对照核验。**

## 一、整体气质

浅色纸质、墨绿书卷气，不是仪表盘。纸张底色 `#FAF6EE`，卡片纯白，主色墨绿 `#1E4638`，次色 `#2E6B52`，点缀赤陶 `#B03A2B` 与陈金 `#A67C3D`。CSS 变量全部集中在 `:root`，业务样式只引用变量。

严禁再引入深蓝 `#1f3864` / `#2f5496`（早期 Excel 配色遗留），已全部清除。

## 二、语义色（一条内容一种色，不许串）

| 语义 | 主色 | 用法 |
|---|---|---|
| 性价比最高 | 金黄 `#E3B94F` | 方案①卡片、性价比列 |
| 本数最多 | 亮绿 `#8BD97B` | 方案②卡片 |
| 绝对价值最高 | 银 `#C6CDD5` | 方案③卡片 + 大卡 |
| 抢下架 / 一切下架相关内容 | 红 `#B03A2B` | 方案④卡片、hero 预警条、风险三卡、风险表头、下架语义 |
| 现在就能买 | 绿 `#2C9921` | 现买好书榜标题竖条 / tag / 表头 |
| 再攒 20 书币 | 蓝 `#1B6FC4` | 下周好书榜同上 |
| 价值评分 | 金 `#9A6B15` | 所有价值评分数字 + 迷你条 |
| 余额 | 金 `#B8860B` | 余额卡数字 |

**新增下架相关内容时，必须挂同一套红**，不要走墨绿表头——这条被明确要求过。

## 三、四方案卡

统一 `linear-gradient(132deg, 浅 → 中 → 稍深)`，**浅底配深字**（浅卡不用白字）：

- ① `#FDF7E1 → #F5DC9C → #E3B94F`，字 `#5A4204`
- ② `#EEFAE8 → #C0EBAF → #8BD97B`，字 `#0F4A16`
- ③ 银要**多点高光**才像金属，单段浅灰会看成脏灰：`#FFFFFF → #E6EAEF → #C6CDD5 → #EDF1F4 → #B7BFC7`，字 `#33404D`
- ④ `#FDEFEA → #F4D1C8 → #E4A795`，字 `#732015`

四卡共用：标题 `#211C15`、目标句 `#3B352B`、小字 `#4C453A`、虚线 `rgba(35,31,25,.16)`。

## 四、方案③ 大卡（`.pickcard`）

浅银金属渐变 `#FFFFFF → #E7EBEF → #C7CED6 → #EEF2F5 → #B5BDC5`，边 `#C3C9D0`，顶部 `inset 0 1px 0 rgba(255,255,255,.9)`。**文字全深色**：标题/数字 `#16212D`，说明 `#3A4550`，标签 `#33404D`，价值评分标金 `#7A5A0F`。进度条槽 `rgba(31,41,51,.14)`，条 `#66737F → #A7B4C2 → #EEF3F8`。

曾用深黑灰 `#232B35 → #35414E → #4C5967`，被否——不符合"银色"主题。**别再改回深底白字。**

class 名必须是 `.pickcard`，不能叫 `.pick`：`.cand.pick` 会命中同一选择器，导致已选书名变白。

## 五、首屏漏斗（5 级「层层收窄」）

绿色**由浅到深**，用 `:nth-child` 控制，不动 HTML：

1. `#F2F9F4` / 边 `#E0EDE4` / 数字 `#4A7A5D`
2. `#E4F1E8` / 边 `#CDE3D3` / 数字 `#406F53`
3. `#D6EBDB` / **淡红边 `#EBBBAE`** / 数字 `#35604A`
4. `#C6E2CD` / **淡红边 `#DE9F8D`** / 数字 `#2A5240`
5. 微信绿渐变 `#0DC267 → #05AE55 → #039A49` + 白字

第 3、4 级是"减法"节点（剔除已下架 / 剔除已读完未买断），**只换淡红边框**，不换底色也不换数字色，否则递进关系断裂。两个减法的数字用大红 `#CC0000`。

终点"真实可买池"必须是**微信绿**，不能是墨绿（用户嫌"太墨绿"，与主题色系脱节）。由于白字在亮绿上天然只有约 2.4:1，这里靠 `text-shadow:0 1px 3px rgba(0,64,32,.42)` 补救——这是全页唯一未达 WCAG AA 的地方，属品牌色妥协，不要扩大范围。

不要用 `opacity: .62` 表达"剔除"：降透明度会让文字发灰。

## 六、对比度红线

所有卡内文字对渐变**最暗端**都要 ≥ 4.5:1（当前最低 4.62）。亮绿 `#40C833`、青蓝 `#39CFFF`、亮金 `#B8860B` 本身**不能直接当小字色**：

- 小字金用 `#9A6B15`（4.68:1），不要用 `#B8860B`（3.26:1）
- 小字绿用 `#2C9921`，小字蓝用 `#1B6FC4`
- 候选卡「微信评分」用淡蓝 `#4590C9`，10.5–11px 下 3.45:1——这是用户明确偏好"更淡"后的下限，再淡就真读不清

改任何颜色都要实算相对亮度，别凭肉眼。

## 七、字体

- 正文：系统无衬线（微软雅黑 / PingFang SC）
- **书名专用行楷**：`"汉仪行楷简","HYXingKaiJ","HYXingKaiS","华文行楷","STXingkai","STKaiti","KaiTi",cursive`。本机通常没有汉仪，实际渲染华文行楷。**一律 `font-weight:400`**——行楷无粗体，faux bold 会糊。
- 应用位置：清单书名列 15.5px、候选卡 16.8px、大卡标题 `clamp(27px,3.15vw,38px)`、对照卡 16.6px
- 「已选」徽章要显式设回无衬线
- 数字用 `font-variant-numeric: tabular-nums`，表格才对得齐

## 八、书名与链接

所有书名走统一函数 `bl(book, wrap=True)`：

- 用数据自带的 `deepLink` 生成 `<a class="bt" target="_blank" rel="noopener noreferrer">`
- `wrap=True` 才加书名号《》，**不要手写 `《{}》`**——那样链接会丢
- 单击即新标签打开，不做双击（会开两个标签）
- 打印时 `.bt` 去下划线

## 九、表格

- 三张清单表列名固定：`# / 书名·作者 / 权益 / 价值评分 / 微信评分 / 标价 / …`，「性价比」不写「每元价值」
- 好书榜要有独立的「评分人数」列，不要塞在评分后面用 `·` 连接
- 下架风险榜要**价值评分与微信评分并列**，方便看出"高评分但高风险"
- 表头文字统一「价值评分」，不写「价值分」
- ≤760px 时所有表格包进 `.scroll` 容器并注入"← 表格可左右滑动查看 →"提示；页面本身不能横向溢出

## 十、文案

- 一句只讲一件事，同一解释只出现一次（候选区不再解释"期刊杂志为空"，因为空卡片里已写）
- 榜单标题与区块 h2 同名：`① 现买好书榜 Top15` / `② 下周好书榜 Top15`
- 首屏只放余额卡 + 下架预警 + 漏斗。**不展示**"书币≠现金 / 开不了会员卡 / 299≠买299"三条约束（用户已知晓）
- 奖励框只讲"每周 20 书币"，不再讲"时长兑书币"，也不再算"+30 预算"
- 不用"风险分"，一律"下架概率 X.X%"
- 不写"每元价值"，写"性价比"

## 十一、Excel 侧差异

- 表头配色沿用旧模板（`2F5496` 深蓝底白字）——与 HTML 不同源，**不要为了统一去改**，会破坏既有使用习惯
- `Alignment(CENTER)` 会 `ValueError`，必须写全 `Alignment(horizontal='center', vertical='center')`
- 同名文件被 Excel 占用时依次退到 `_new.xlsx` 再退到旧名，不要直接抛错
- 说明性内容（可获取信息 / 互动证据 / 口径说明）已移出工作簿，**不要加回去**
