# 价值评分与购书方案算法

## 一、为什么要自己算一遍评分

微信读书的「推荐值」是**样本量无关的算术均值**：9.0 分的书可能只有 27 个评分人，也可能有 26 万人。直接按它排序，等于让"小样本高分"和"大样本高分"平起平坐。价值评分要做的事是：**把"这个分数有多可信"单独拆出来，乘回去**。

四层结构，每层只解决一个偏差：

| 层 | 要解决的问题 | 手段 |
|---|---|---|
| ① 统计下界 `conf_stat` | 评分人数少 → 均值不可信 | Wilson 单侧 95% 下界 ÷ 原始分 |
| ② 类内相对度 `rel_eff` | 不同类型书的评分基线不同（计算机普遍虚高） | 参与率 ÷ 同类型几何均值，再开方压缩 |
| ③ 互动证据 `fac_e` | 只看"投票"看不出真实质量 | 人均划线密度、人均想法密度 |
| ④ 受众面 `heat` | 读者规模差异 | Hill 曲线，只做 ±5% 微调 |
| ⑤ 封顶 `cap` | 四个乘数上限叠乘会把置信度推到 1 | 随原始分上升的封顶 |

## 二、公式

```
score = raw × min( conf_stat × rel_eff × fac_e × heat , cap )

cap       = min(1, (raw / 91) ** 0.5)          # 9.1 分以下不允许打满
conf_stat = wilson_lcb(raw/100, ratingCount, z=1.645) / (raw/100)
rel_eff   = clip( (参与率 / 同类型几何均值) ** 0.5 , 0.65, 1.12 )
heat      = 0.95 + 0.10 × Hill(阅读人数百分位)
fac_e     = clip( (conf_e / 0.80) ** 0.40 , 0.88, 1.06 )
```

其中：

- **Hill 曲线**：`Hill(x, k) = x^n / (k^n + x^n)`，`n` 由 `solve_n(k, at_mean, floor, ceil)` 解出，使 `x = k` 时正好落在均值线上；当前 `k=0.70`、`n=3.0801`。
- **参与率**：`ratingCount / readingCount`。跨类型差异极大，所以只在**同类型内部**相对化。
- **互动密度**：`d_mark = 热门划线 Top10 累计人次 / 阅读人数`，`d_idea = 想法数 / 阅读人数`，做伪读者数 `K_PSEUDO=200` 的贝叶斯平滑，再乘阅读人数做 log 回归剔除热度成分，`x_e = x_mark^0.55 × x_idea^0.45`。
- **所有参数集中在 `score_value.py` 顶部**，并写进 `_valuescore5.json` 的 `params`；`build_excel.py` 的 `score_like_shelf()` 从 `params` 读，保证"书单里未加架的书"用同一套曲线复算，两处同源。

### 关键教训（改参数前必读）

1. **热度不能当可信度乘数**。早期版本用 `Hill(阅读人数, 指数 3.08)` 直接放大，把"小众"判成"不可信"，《棋经十三篇》83.1 分被打到 23.7。样本量用 Wilson 下界解决，受众面只做 ±5%。
2. **封顶不能取常数 1**。四个乘数上限叠乘 = `1.12 × 1.06 × 1.05 = 1.246`，足以把任何 `conf_stat` 推到 1。实测常数封顶时 491 本（36.9%）「价值分 = 平台评分」，模型在它们身上完全退化。改成 `cap = (raw/91)^0.5` 后打满只剩 2.2%，且全部 ≥ 9.1 分。
3. **改了曲线必须整链重跑**。分类基准、四方案入选书目、方案③选中书、清理候选全部连动。

## 三、四套购书方案

共同前提：候选池 = **单本标价 ≤ 余额** 且**未下架** 且**未读完**（已读完的书不产生"永久授权"增量）。

| # | 名称 | 算法 | 目标函数 |
|---|---|---|---|
| ① | 性价比最高 | 只在**有评分**的书里，按 `价值评分 ÷ 标价` 降序贪心装满预算 | `Σ vscore / Σ price` |
| ② | 本数最多 | 0/1 背包，本数优先，同本数取价值评分和最大 | `Σ vscore`（约束 `n` 最大） |
| ③ | 绝对价值最高 | 一次只买 1 本。候选 = 15 个标准一级分类各取综合价值 V 前 2；在这些候选里挑 `V × 标价` 最大的一本 | `V × price` |
| ④ | 抢下架 | 只看价值评分 ≥ 70 的高价值书，0/1 背包最大化 `Σ(下架概率 × 价值评分)` | `Σ risk × vscore` |

**方案 ②③ 曾互换过**，用户明确：②=本数最多，③=绝对价值最高。

### 综合价值 V（只用于方案③）

```
V = 0.45 × 价值评分 + 0.25 × 平台原评分
  + 0.15 × 参与率池内百分位 + 0.15 × 阅读人数池内百分位
```

价格不进 V。单本购买不追求性价比，所以按 V 排序而不是 V÷价格；但在候选之间用 `V × price` 排序——只买一本时没有"数量"可摊薄，标价越高剩余越少，V 越高这本书越值。

**15 个标准一级分类**的口径与「分类基准与类型评分」第一节完全一致：取 `typestat.c1` 中「有评分 ≥ 10 本」且非「未分类」的分类。这个口径出现两处（方案③候选、分类基准表），改一处必须同步另一处。

## 四、下架概率

```
risk = 100 × (0.5 × 权益类型下架率 + 0.3 × 出版年份段下架率 + 0.2 × 冷门度段下架率)
```

三个分量都来自**书架实测**（不是拍脑袋打分），用 Laplace 平滑：`(命中 + 0.5) / (总数 + 1)`。

- 它是**百分比**，展示一律 `%.1f%%`
- 权益类型：付费会员卡可读 / 体验卡可读 / 永久可读 / 免费
- 冷门度：阅读人数分档

## 五、书架清理候选

只列 **价值评分 < 40** 的书，并按处置难度分三层：

1. 未买断 → 优先清理（本来就没付钱，删掉零成本）
2. 已买断 → 可清理（沉没成本，看是否还会读）
3. 在读或已读 → 暂缓（删了会丢进度/记录）

## 六、口径边界

- **书币 ≠ 现金**：不能提现、不能开会员卡。
- **单本 ≤ 余额的 N 本 ≠ N 本都买得起**：方案预算都是逐本累加到花完。
- **兑换进度无接口**：网页端 20 条候选路径全 404，已领书币只能在 App「我 → 福利」看。拿不到就写"未读到"。
- **朋友在读无接口**：`/web/book/friend*`、`/web/discover/interact*` 全 404，只能用想法数/划线数/点评数/评分人数的百分位作为共识度代理。
- 划线总人次无公开接口，只有单本「热门划线 Top10」的累计人次。
